
# Full Modular Backend Refactoring Plan — CodeSpectra

## Current Problem
Your backend is a **monolith**: `ai_router.py` contains ALL API routes in one file. Every page's backend logic is tangled together — when you fix one page's API, you risk breaking another. There's no separation of concerns.

## Current Architecture
```
backend/
├── server.py          (132 lines - FastAPI proxy, health checks)
├── ai_router.py       (ALL routes in ONE file - monolithic)
├── ai_client.py       (AI client utilities)
├── rag.py             (RAG functionality)
└── requirements.txt
```

## Implementation Steps

### Step 1: Create Core Infrastructure
**Files**: `core/database.py`, `core/config.py`, `core/auth.py`, `core/dependencies.py`

- **`core/config.py`** — Extract env var loading (MONGODB_URI, MONGODB_DB_NAME, API keys, etc.) into a Pydantic `Settings` class
- **`core/database.py`** — Single MongoDB connection manager using `motor.motor_asyncio` (async MongoDB driver)
  ```python
  # Shared across all services
  client = motor.motor_asyncio.AsyncIOMotorClient(settings.MONGODB_URI)
  db = client[settings.MONGODB_DB_NAME]
  
  # Helper to get collections
  def get_collection(name: str):
      return db[name]
  ```
- **`core/auth.py`** — Extract auth middleware from current server.py
- **`core/dependencies.py`** — FastAPI `Depends()` functions for DB access, auth, etc.

### Step 2: Create Pydantic Models
**Files**: `models/*.py`

- Define **request/response schemas** for each feature
- These replace inline dict handling in ai_router.py
- Include validation, serialization, and documentation
- Shared base models in `common.py` (error responses, pagination, etc.)

### Step 3: Create Service Layer
**Files**: `services/*.py`

- Extract all business logic from ai_router.py into service functions
- Each service handles its own MongoDB collection(s)
- Services contain all CRUD operations:
  ```python
  class ChallengeService:
      def __init__(self, db):
          self.collection = db["challenges"]
      
      async def get_all(self, filters=None):
          ...
      async def get_by_id(self, id):
          ...
      async def create(self, data):
          ...
      async def update(self, id, data):
          ...
      async def delete(self, id):
          ...
  ```
- Each service is testable independently with mocked DB

### Step 4: Create Route Files
**Files**: `routers/*.py`

- Each router is a `APIRouter()` that gets mounted on the FastAPI app
- Routes are **thin** — they call service methods, return responses
- Group by feature domain:
  - `challenge_routes.py` → `/api/challenges/*`
  - `interview_routes.py` → `/api/interviews/*`
  - `analytics_routes.py` → `/api/analytics/*`
  - `hackathon_routes.py` → `/api/hackathons/*`
  - `dashboard_routes.py` → `/api/dashboard/*`
  - `settings_routes.py` → `/api/settings/*`
  - `cert_routes.py` → `/api/cert/*`
  - `achievements_routes.py` → `/api/achievements/*`
  - `docs_routes.py` → `/api/docs/*`
  - `scanner_routes.py` → `/api/scanner/*`
  - `auth_routes.py` → `/api/auth/*`
  - `integrations_routes.py` → `/api/integrations/*`
  - `ai_routes.py` → `/api/ai/*`

### Step 5: Rewrite server.py
- Mount all routers:
  ```python
  from fastapi import FastAPI
  from routers import challenge_routes, interview_routes, analytics_routes, ...
  
  app = FastAPI()
  app.include_router(challenge_routes.router, prefix="/api")
  app.include_router(interview_routes.router, prefix="/api")
  # ... etc
  ```
- Remove all route logic from server.py (keep only app setup + proxy if needed)
- Remove ai_router.py entirely (replaced by modular routers)

### Step 6: Write Tests
**Files**: `tests/test_*_routes.py`

- One test file per router
- Test CRUD operations for each endpoint
- Use `httpx.AsyncClient` with FastAPI test client
- Mock MongoDB using `mongomock` or testcontainers

### Step 7: Update Frontend (if needed)
- The frontend API calls should remain the same if route paths don't change
- Verify each frontend page still works with the new backend

## Migration Strategy (Safe Rollout)
1. **Phase 1**: Create `core/` infrastructure alongside existing code (no breaking changes)
2. **Phase 2**: Create models and services for ONE feature (e.g., challenges)
3. **Phase 3**: Create router for that feature, test it end-to-end
4. **Phase 4**: Repeat for each feature, one at a time
5. **Phase 5**: Mount all new routers in server.py, remove old ai_router.py routes
6. **Phase 6**: Write comprehensive tests

## Key Principles
- **Each feature owns its routes, services, models, and tests** — no cross-feature coupling
- **Services handle all DB access** — routes never touch MongoDB directly
- **Shared code lives in `core/`** — database, config, auth, common utilities
- **Reusable CRUD base class** — services can inherit from a `BaseService` for common patterns
- **All existing API paths stay the same** — zero frontend changes needed
